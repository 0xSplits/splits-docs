# The basics - start here

*Last update 08 May 2026*

Welcome and thanks for being an early part of Splits! We're going to cover a few terms and principles upon which the product is built: Team, Person, and Account.

![](/images/the-basics/img-1.png)

# Team

This is the primary organizational unit the product is built around. With the exception of your own personal settings (more on that below), everything you see in the app—accounts, balances, transactions, bank info, etc—is scoped to the team you're currently viewing. You can see which team you're viewing in team selector in the top left.

![](/images/the-basics/img-2.png)

Since you can be part of multiple teams, we recommend creating a new team for each entity you intend to manage within Splits. You can create a new team by clicking on the team selector in the top left and selecting "Create a team".

![](/images/the-basics/img-3.png)

We think of each team as being it's own *entity*, since it's designed to group people together within a shared workspace. Additionally, in order to turn on features like on/offramps and compliant payments, you need to complete *legal entity verification* (i.e., KYB or KYC) and **each team can only have one legal entity verified**.

For example, Alice is a member of both Splits Labs team and her own personal team. Splits Labs and Alice have different tax identification numbers (EIN and SSN, respectively), and therefore each has a distinct team within the product. Although you don't need a tax identification number to use Splits, we think it's a helpful litmus test for whether a separate team is needed.

A litmus test to help decide when to create a new team vs use an existing one is, "who are the owners of this team?" If the owners are the same, it probably makes sense to use the existing team. If they're different, it's probably worth creating a new one. This is relevant when it comes to Recovery. See [Change recovery signers](/faqs/change-recovery-signers) for more.

# Person

This is how you, as an individual, interface with each team you're part of. A person authenticates using email and can be part of multiple teams. Each person can save passkeys. These passkeys can then become signers on accounts.

![](/images/the-basics/img-4.png)

Each person's passkeys stay with them across every team they're a member of. For example, Alice (Person) has an iCloud passkey. This means that Alice can use that iCloud passkey to sign transactions on any of account they're a signer on, regardless of which team the account is associated with.

A person can also change their email address, display name, and avatar. These also persist across each team you're part of. Personal settings can be found within the [Settings page](https://app.splits.org/settings/personal/general/).

![](/images/the-basics/img-5.png)

# Account

This is where assets are stored within your team. Accounts exist across networks (i.e., Ethereum, Base, Optimism, etc) and each account has the same address on every network.

![](/images/the-basics/img-6.png)

Each account has signers. Signers are public keys that have the ability to approve transactions from the account. For accounts within Splits, these signers are the public key of the passkeys each person has saved. The public key is stored onchain. The private key is stored only in the password manager you choose (i.e., iCloud Keychain, Google Password Manager, Yubikey, 1Password, BitWarden, etc). For more tips on passkeys, see [Passkey not opening](/faqs/passkey-not-opening)
